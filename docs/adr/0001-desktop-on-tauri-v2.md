# 0001. Desktop on Tauri v2

## Status

Accepted, 2026-10-24. Deciders: Kaan.

## Context

Electron ships Chromium and Node with every install. The desktop backend is TypeScript while iOS runs the Rust core, so the sync protocol has two implementations that stay equal only through conformance vectors. The costs are:

- install size and memory, because each install carries its own Chromium and Node;
- a second sync and CRDT implementation next to the one in `crates/memry-core`;
- native modules built against the Electron ABI (`apps/desktop/AGENTS.md:81-88`).

## Decision

1. One Tauri v2 build (`tauri` 2.12 line) replaces the Electron build in place on macOS 13+ (arm64, x64), Windows 10 1809+ (x64, arm64) and Linux x64 (glibc 2.35+, WebKitGTK 4.1). The system webviews are WKWebView, WebView2 Evergreen and WebKitGTK.
2. The backend has no Node.js and no JavaScript runtime. It is Rust on `crates/memry-core`, plus new crates: `memry-desktop` (OS services, no tauri dependency), `memry-ml` (ONNX Runtime, whisper, Tesseract, images, pdfium; OCR and pdfium run in its `memry-ml-worker` sidecar process, so a hung native call is killed without taking the app down), `memrynote-cli` (the `memrynote` CLI) and the bin crate `memry-tauri` in `apps/desktop-tauri/src-tauri`.
3. The renderer is copied to `apps/desktop-tauri/src/renderer` and keeps its React code, look and behavior. IPC types are generated from Rust with tauri-specta.
4. The markdown converter is a Rust port in `crates/memry-core/src/markdown/`, proven byte for byte against vectors generated by the frozen TypeScript converter and fuzzed over real vaults.
5. Core databases live at `<vault>/.memry/core/data.db` and `index.db` under the memry-core schema. The Electron `<vault>/.memry/data.db` and `index.db` are read once by the first-launch migration and never written. memry-core refuses to open a database that holds a `__drizzle_migrations` table. `index.db` is derived: a lower `user_version` migrates in place, and the file is deleted only when it is corrupt or newer than the build understands, so embeddings survive index migrations.
6. The identity stays the same: bundle id `com.memrynote.memry`, product name `MemryNote`, Apple Team ID and Windows Authenticode certificate. Velopack updates all three OSes, with bridge feeds for installs still running electron-updater. macOS 12 users stay on the last Electron release and keep syncing.
7. Secrets stay in the OS keychain through `keyring-core` 1.x and its platform store crates, with the same account names as Electron, under the app's own service `com.memrynote.memry` and `com.memrynote.memry.<feature>`. Amended by Step 15 (#3532), stage 15a3, which replaced `com.memry.sync`: Electron moves each of its keychain items into its own encrypted file and deletes the keychain copy (`apps/desktop/src/main/secrets/secret-storage.ts:436`, `:518`), so a secret Tauri kept there could vanish under a running Electron or be taken over by it. Tauri reads Electron's secrets only through the first-launch migration (Step 37 (#3554)) and never writes Electron's services. One rustls stack with the `ring` provider serves every HTTP and WebSocket client, through the shared client `memry_desktop::http::client()`. The extension capture server is app-scoped and survives vault switches, as in Electron. Every other long-lived task stops on vault switch, sign-out and shutdown.
8. Nothing ships before the last step of the epic. The last steps delete the Electron app, `packages/app-core`, Playwright and the Electron-only tools.

## Consequences

- Compatibility obligations hold across the move: vault files, the sync protocol, settings shapes, the CLI, MCP tools, deep links and release asset names stay exact.
- Dual-renderer rule: a critical renderer fix lands in both `apps/desktop/src/renderer` and `apps/desktop-tauri/src/renderer` in the same PR until the cutover.
- Citation rule: after the cutover every normative citation in `docs/protocol/` points at the Rust implementation. Step 42 (#3559) rewrites the citations and Step 43 (#3560) runs the citation check.
- Cost: two renderers live in the repo for the length of the epic.

## Rejected alternatives

| Alternative                               | Why rejected                                                                                                                                                                                                                                                                                   |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tauri with a Node sidecar                 | Keeps a JavaScript runtime in the backend, which the epic forbids, and keeps two sync and CRDT implementations.                                                                                                                                                                                |
| Tauri v3 with CEF                         | Tauri v3 is alpha only (`3.0.0-alpha` on crates.io on 2026-10-24). CEF would also bring back a bundled Chromium and the install size this move removes.                                                                                                                                        |
| Electrobun                                | Bun and TypeScript backend, so the same two-implementation problem, and a young runtime.                                                                                                                                                                                                       |
| Wails                                     | Go backend. The sync, crypto and CRDT core is Rust and shared with iOS.                                                                                                                                                                                                                        |
| Flutter                                   | Would rewrite the React renderer and BlockNote editor, which are the product.                                                                                                                                                                                                                  |
| Qt                                        | Same renderer rewrite, plus a C++ or QML stack beside the Rust core.                                                                                                                                                                                                                           |
| Hidden converter webview                  | Keeps BlockNote as the only markdown converter and leaves a webview in the backend path. Background conversion would depend on a window the user never sees.                                                                                                                                   |
| rquickjs (embedded QuickJS)               | A JavaScript runtime in the backend, and BlockNote needs DOM APIs that QuickJS does not provide.                                                                                                                                                                                               |
| Keeping the drizzle schema in the new app | The desktop drizzle schema (`packages/db-schema/src`) and the core migrations (`crates/memry-core/src/storage/migrations/data/`) define more than twenty table names in common with independent columns, so one database file cannot satisfy both owners. The core schema is the single owner. |
