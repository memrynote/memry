# MemryNote Mobile — Implementation Plan Index

**Status:** Program index · **Date:** 2026-07-14 · **Owner:** Kaan
**Spec:** [`docs/superpowers/specs/2026-07-13-mobile-app-design.md`](../specs/2026-07-13-mobile-app-design.md)

## Goal

Ship a full-featured Expo / React Native app (iOS + Android from day one) that is a first-class E2E-encrypted sync peer with the desktop app — feature parity on notes, journal, tasks, projects, calendar, inbox, home, search, tags, folders, and settings, plus mobile in-app purchases. Offline-first, byte-for-byte wire-compatible with desktop, phased to beta-early → store launch at full parity (D3).

## Architecture

The codebase is already ~60% of the way to a portable kernel. This program **extracts** the sync engine, crypto, CRDT provider, and markdown/editor pipeline out of `apps/desktop/src/main` into host-agnostic `@memry/*` packages behind dependency-injection seams, keeping desktop green at every step, then builds `apps/mobile` on top of those packages with mobile adapters. UI and kernel share one JS runtime on mobile (no IPC transport — the `@memry/contracts` types survive as function signatures). SQLite (SQLCipher) is canonical on mobile; note/journal bodies are Y.Docs persisted as a SQLite update-log; BlockNote is hosted in a WebView / Expo DOM component running the exact same serializer as desktop. Server changes are additive and deploy before clients.

## Tech Stack

Expo SDK 57 (RN 0.86, React 19.2, New-Architecture only) · expo-router · op-sqlite `@^17` (SQLCipher + FTS5) + Drizzle `@^0.45.2` · react-native-libsodium `@^1.7` + `@noble/curves` + `bip39` shims (desktop: libsodium-wrappers-sumo `@^0.8.2`) · Yjs `~13.6.29` + y-protocols `^1.0.7` · `@blocknote/*` `0.47.x` (DOM/WebView only, never on Hermes) · cborg `^4.5.8` · zod `^4.3.4` (matches `@memry/contracts`) · react-native-mmkv · expo-secure-store · react-native-purchases (RevenueCat) `^9` · EAS Build + Submit + Update.

## Global Constraints

These apply to **every** sub-plan in this program.

- Backward compatibility is MANDATORY for production installs: every change must work for existing installs, no DB resets, sync protocol / IPC contracts / vault file formats / settings shapes must tolerate data written by older app versions.
- DB schema changes go through additive, hand-written D1/data-DB migrations that preserve existing rows (Drizzle snapshots broken past 0021; data-DB migrations are hand-written).
- Sync-server deploys BEFORE desktop/mobile clients for every additive change (D6 sync item types, D8 settings-push, entitlement_grants).
- Crypto parameters are IMMUTABLE and byte-identical across clients: Argon2id v1.3 ops=3, mem=64 MiB, parallelism=1; BLAKE2b crypto_kdf_derive_from_key with exact 8-char contexts (memryvlt/memrysgn/memryvrf/memrykve/memrylnk/memrymac/memrysas); base64 = sodium.base64_variants.ORIGINAL (standard alphabet, padded); cryptoVersion=1; canonical CBOR in CBOR_FIELD_ORDER.
- E2E-encrypted: server never sees plaintext; it verifies Ed25519 via WebCrypto and validates envelope lengths only.
- Offline-first: SQLite local storage is canonical on mobile; CRDT (Yjs) for note/journal bodies, field-level vector clocks for tasks/projects/calendar; correctness never depends on background execution.
- `@blocknote/*`, `yjs`, and `zod` pinned IDENTICALLY to desktop across clients; a CI check fails the mobile build on drift; BlockNote bumps gated on the markdown round-trip / byte-preservation golden suite.
- `@memry/contracts` is the single wire-format source of truth; mobile MUST import, never copy (copying breaks cross-device crypto/signature interop).
- No Co-Authored-By trailer on commit messages.
- Prettier: single quotes, no semicolons, 100-char width, no trailing commas.
- RTL safety: new code uses logical Tailwind/RN props (ms-/me-, ps-/pe-, start-/end-) that flip automatically in RTL; RN uses `I18nManager.forceRTL` instead of `document.dir`.
- Extraction principle: move files, re-export from old paths, tests move with the code, desktop consumes the new package first — each extraction keeps desktop green, verified by the existing suite before mobile exists.
- Logging via `createLogger('Scope')` seam (never raw `console.*`); user-facing errors via `extractErrorMessage(err, fallback)`.
- WCAG AA + reduced-motion + RTL accessibility per PRODUCT.md; personality calm, private, crafted.

## Execution order & the Phase-0 gate

**Two tracks run in parallel from the start.**

1. **The extraction track keeps desktop green and can start now.** `serverdesktop` (additive server + desktop prep) has no dependencies and ships server-first. The five extractions — `@memry/crypto` → `@memry/sync-engine` / `@memry/crdt-core` → `@memry/platform` + `@memry/app-kernel` — are pure move-and-re-export refactors verified by the existing desktop suite. `extract-sync-engine` and `extract-crdt-core` both depend on `@memry/crypto` landing first (they route encrypt/decrypt/token-manager/crdt-encrypt through it); `extract-platform-app-kernel` waits on both the sync-engine and crdt-core extractions so the kernel can consume the finished seams. None of these need a phone to exist, and each one upgrades desktop before mobile.

2. **Phase 0 spikes gate the mobile-specific plans.** The five go/no-go spikes (libsodium byte-compat, Yjs-on-Hermes perf, BlockNote-in-WebView, op-sqlite triple-flag, pnpm isolated-install) must be green before committing the timeline. Concretely: `extract-crypto` is gated by the libsodium byte-compat spike, and `extract-editor-web-markdown` is gated by the BlockNote-in-WebView spike; **every** deferred mobile plan is `gatedByPhase0: true`.

**Critical path:** `phase0` → `extract-crypto` → `extract-sync-engine` + `extract-crdt-core` → `extract-platform-app-kernel` → `mobile-scaffold-local-data` → (`mobile-crypto-adapter-auth-linking`, `mobile-sync-client-item-handlers`) → `mobile-editor-surface` → feature UIs → `mobile-testing-eas-ci` → store launch. The extraction is the long pole and parallelizes once the crypto seam lands.

**Editor-spike failure → source-mode-first re-plan.** If the BlockNote-in-WebView spike fails, `mobile-editor-surface` routes to source-mode-first: the raw `TextInput` markdown fallback ships as the primary editor (it is already scheduled to ship first anyway to de-risk the timeline), and the WebView BlockNote surface becomes a fast-follow. This does not block auth/sync/read beta (Phase 2) — only the rich-editing surface.

- **Native Google OAuth (§6 / §17, phase 2)** — iOS/Android Google client + custom-scheme / App-Links redirect allowlist. Launch ships OTP-only (zero server change, covered by `mobile-crypto-adapter-auth-linking`); add native Google sign-in later.

Both optional; fold into `serverdesktop` or `mobile-sync-client-item-handlers` when prioritized.
- **Custom themes (§13)** — base + hex-override themes would be a 17th sync item type; DEFERRED (already noted in `mobile-theming-i18n-telemetry`).
- **iPad (D10)** — phone-only v1 is a deliberate exclusion, not work; iPad split-view / hardware-keyboard / wide layouts are a post-v1 fast-follow (no plan needed until scheduled).

## How to execute

Run each sub-plan with **`superpowers:subagent-driven-development`**: dispatch one fresh subagent per task, with a review gate between tasks. Every task in the detailed plans is strict TDD — a failing test, minimal implementation, a real verify command, then a conventional commit (no Co-Authored-By trailer). Do not batch tasks into one agent; the review checkpoint after each task is what keeps desktop green and catches seam-contract drift early. For the extraction plans, the existing desktop suite (`pnpm --filter @memry/desktop test:main` / `typecheck` / `pnpm check:architecture` / `pnpm ipc:check`) is the green gate after every move. Write a deferred plan only when its trigger above is satisfied; then execute it the same way.
