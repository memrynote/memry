# Hero Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship four throwaway prototype routes (`/1`, `/2`, `/3`, `/4`) on the Memry landing site that each render a different hero treatment under the existing `Header`, with the header rendered transparent over the hero and reverting to its glass pill once the hero scrolls past — so we can compare and pick a winner live.

**Architecture:** Reuse the existing `Header`/`Footer`/`FeatureFlow`/`Pricing` sections. Add a single `transparent` prop to `Header` that swaps its pill classes and attaches an `IntersectionObserver` to a `[data-hero-end]` sentinel rendered by a shared `LabFrame`. Each variant page renders `<LabFrame>{variantHero}</LabFrame>`. New code is isolated under `apps/landing/src/pages/HeroLab/` and `apps/landing/src/components/hero-lab/` so it can be deleted in one commit once the winner is chosen.

**Tech Stack:** React 19 + react-router-dom 7 + framer-motion + Tailwind v4 + Vite. No new dependencies. Landing has no Vitest, so verification is `pnpm --filter @memry/landing typecheck`, `pnpm --filter @memry/landing lint`, `pnpm --filter @memry/landing build`, plus a Playwright MCP click-through against the running dev server.

**Spec:** `docs/superpowers/specs/2026-05-17-hero-lab-design.md`

## Task 2: Wire IntersectionObserver to `[data-hero-end]` sentinel

**Files:**

- Modify: `apps/landing/src/components/layout/Header.tsx`

- [ ] **Step 1: Import `useEffect` and `useRef`**

Locate the top of `Header.tsx`. The current React import is:

```tsx
import { useState } from 'react'
```

Replace with:

```tsx

```

- [ ] **Step 2: Add sentinel-driven internal state**

Inside the `Header` function body, right after the `useState(false)` for `mobileMenuOpen`, add:

```tsx
const [heroVisible, setHeroVisible] = useState(transparent)
const observerRef = useRef<IntersectionObserver | null>(null)
```

`heroVisible` defaults to `transparent` so the first paint matches the initial prop (avoids a one-frame flash of glass-pill on routes that want to start transparent).

- [ ] **Step 3: Replace `navSkin` to be driven by `heroVisible` instead of `transparent`**

Replace the `const navSkin = ...` line added in Task 1 with:

```tsx
const onImage = transparent && heroVisible
const navSkin = onImage
  ? 'border-transparent bg-transparent shadow-none backdrop-blur-0 backdrop-saturate-100 dark:border-transparent dark:bg-transparent dark:shadow-none'
  : 'border border-white/70 bg-paper/60 shadow-[0_4px_30px_rgba(0,0,0,0.06),inset_0_1px_0_rgba(255,255,255,0.6)] backdrop-blur-2xl backdrop-saturate-150 dark:border-white/8 dark:bg-paper/55 dark:shadow-[0_4px_30px_rgba(0,0,0,0.5),inset_0_1px_0_rgba(255,255,255,0.04)]'
```

`onImage` is the local boolean we'll reuse for the data-attr in Task 3.

- [ ] **Step 4: Add the sentinel observer effect**

Below the existing `handleLogoClick` callback (the function at line ~269 in the original file), add:

```tsx
useEffect(() => {
  if (!transparent) return

  const setup = () => {
    const sentinel = document.querySelector('[data-hero-end]')
    if (!sentinel) return false

    observerRef.current?.disconnect()
    observerRef.current = new IntersectionObserver(
      (entries) => {
        for (const entry of entries) {
          // Hero is "visible" (sentinel below the top of the viewport) when
          // boundingClientRect.top > 0. Once the sentinel scrolls above the
          // top of the viewport, we want the glass-pill back.
          setHeroVisible(entry.boundingClientRect.top > 0)
        }
      },
      { threshold: 0, rootMargin: '0px 0px 0px 0px' }
    )
    observerRef.current.observe(sentinel)
    return true
  }

  if (!setup()) {
    const raf = requestAnimationFrame(() => setup())
    return () => {
      cancelAnimationFrame(raf)
      observerRef.current?.disconnect()
      observerRef.current = null
    }
  }

  return () => {
    observerRef.current?.disconnect()
    observerRef.current = null
  }
}, [transparent])
```

This effect:

- No-ops when `transparent` is false (real routes unaffected).
- Tries to find the sentinel on mount. If not in the DOM yet (timing race), retries once on the next animation frame.
- On every intersection event, updates `heroVisible` from the sentinel's position relative to the viewport top.
- Cleans up the observer on unmount or when `transparent` flips.

interface LabFrameProps {

- `noindex` so the prototype URLs don't get crawled.
- Switcher rendered last so it overlays everything.
