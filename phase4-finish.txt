## Known bugs and platform facts — do not rediscover

1. **A permanently-rejected record wedges the whole outbox.** A `400` for one item's type fails the
   **batch**, the row keeps `attempt_count 0` with no backoff, and it retries forever. **The most
   serious open item in the tree**, and it is why a non-2xx must cross the transport as a *response*
   and why no copy may describe a permanent refusal as transient.
2. **Pull-then-push is not a convenience.** A client that pushes a field-merged type **without
   pulling first** silently destroys a concurrent peer's field, and no later pass repairs it.
   `SyncEngine::run_pass` does pull-then-push; any shell-driven sync must too.
3. **A whole-fragment replace loses concurrent edits** (88, chapter 12 §12.5.0.1). Anything that
   re-seeds a document from an external source of truth is an authoritative overwrite, not an edit.
4. **A delete must tick its clock** or the server accepts it and does nothing (§6.9.1).
5. **§7.15's runtime obligation is reported, not performed** — now T158's (100).
6. **`Reachability::observe` has a shell caller now, and can never have a Rust one** until band B3
   (107). The shell half is wired and tested; the core cannot hold the seam.
7. **`snapshot_is_due` has no caller** — now T158's (100).
8. A no-op pull costs **32–36 s** on a 94-note vault. Use `memry notes fetch <id>` (0.4–1.8 s) when
   measuring anything.
9. **"The fourth OTP request hangs" was never a hang** (109). The ladder turns a 429's `Retry-After`
   straight into the delay **with no ceiling**, and the per-IP limiter is 10 per **3600 s** with
   `Retry-After` set to the remaining window — so an eleventh call suspends for up to an hour. And it
   **cannot be interrupted**: `rust_future_cancel` appears **zero** times in the generated bindings,
   so cancelling the Swift `Task` does not stop an in-flight core call (108). T147's answer is
   structural — a hard cap of three code requests per address — never a Cancel button that cannot
   cancel. **Capping the honoured delay in the core's ladder is a decision for Kaan, not a task.**
10. **Only `Transport` and `SecureStore` can be handed to the core** (107). The only exported
    constructor taking any seam is `AuthSession.init(transport:secureStore:baseUrl:clientPlatform:device:)`.
    `FileProtection`, `Reachability`, `CodeCapture`, `Notifications`, `BackgroundExec` and
    `EditorHost` are accepted by nothing; `SyncEngine` and `RealtimeClient` appear zero times in the
    generated Swift. Seams the **shell** drives itself are all reachable — T155 calls
    `openingVault` directly, T153 calls `scan()` directly. Do not try to hand the others to the core.

## iOS facts that cost a session each

- **`swiftlint --strict --path <file>` does not exist** on SwiftLint 0.65.1. Use
  `cd apps/ios && swiftlint lint --strict <paths>`, run from `apps/ios` so the config and the nested
  `MemryTests/.swiftlint.yml` are found.
- **Run BOTH gate forms before declaring a wave green.** iOS CI was red on `main` for the whole of
  Phase 3 and half of Phase 4 and nobody noticed (112), because the per-file `swiftlint` the briefs
  prescribe passes while CI runs it project-wide. **The gate the tasks ran was not the gate CI ran.**
  Run a bare `swiftlint lint --strict` from `apps/ios` and `pnpm check:architecture` every wave, and
  check `gh run list --workflow=ios-ci.yml --limit 3` before you believe main is green.
- **`-only-testing:` with a name that matches nothing runs nothing and prints `TEST SUCCEEDED`**
  (106). **Swift Testing suite names are struct names, not file names**, and they diverge freely —
  `TransportTests.swift` holds `TransportHTTPTests` and `ResponseBodyTests`. A run once reported
  **64 passed** where the truth was **102**. Derive the names from the source and **precompute the
  expected total before reading the result**; the failure mode is a plausible smaller number, not an
  error. A function filter needs trailing parens: `.../myTest()`. An unmatched filter list makes
  xcodebuild reject the whole run with `result unknown` — build the argument list as a shell array,
  not one interpolated string.
- **`xcodebuild` lies about the count.** Swift Testing suites are invisible to the XCTest counter: a
  run that executed 160 tests prints `Executed 0 tests ... ** TEST SUCCEEDED **`. Real numbers only
  from `xcrun xcresulttool get test-results summary --path <bundle>.xcresult`.
- **The `Unit` plan is hermetic now.** The B0 spikes were deleted (their own README said to, once
  phase C1 replaced them), which removed the live-staging S2 case that hung the plan (93). The bare
  plan is safe to run. `SpikeS4Tests` survives as T082's harness.
- **The simulator is not the device.** It does not implement data protection at all, has no camera,
  has no keychain lock state, and runs on the host CPU with host memory. Assertions about those
  **pass with the code under test deleted**. Simulator evidence is evidence for the simulator, and a
  test written about an environment must branch on `targetEnvironment(simulator)` and skip rather
  than vacuously pass off-device.
- **The entitlement is a floor, not a default** (113). A file explicitly set to `.none` still reads
  back as `completeUntilFirstUserAuthentication`. Also: `URL.resourceValues` answers
  `NSURLFileProtection…` while `FileProtectionType.rawValue` is `NSFileProtection…` — comparing raw
  strings across the two APIs fails on a *correctly* protected file.
- **The generated bindings are their own target at Swift 5**, because UniFFI 0.32.1 emits code Swift
  6 rejects. **`MemryCore` itself stays at Swift 6.** Do not undo this. `Package.swift` links `libz`
  (spec-defect 49). Do not undo this either.
- **Regenerate the bindings whenever the UniFFI surface changes**, then confirm
  `git diff --exit-code packages/swift/MemryCore/Sources/MemryCore/Generated/` is clean and update
  `contracts/core-api.md`. **No gate catches a stale binding** — Phase 3 ended with one.
- `Thread.isMainThread` and `Thread.current` are unavailable from an async context under Swift 6; use
  `pthread_main_np()`. And a main-thread assertion does not evidence the executor — assert the queue
  label (91).
- **No `project.pbxproj` edit is needed for a new file.** The project uses
  `PBXFileSystemSynchronizedRootGroup` for `Memry`, `MemryTests`, `MemryUITests` and
  `MemryConformanceTests`.
- Turn off the simulator's hardware keyboard (⇧⌘K) before any editor or toolbar test, and dismiss the
  QuickPath overlay — both make a correct toolbar look absent with no error (R16).
