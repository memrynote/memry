## THE LESSON FROM PHASE 3 — it cost five bugs and it will recur here

**A tier can be fully implemented, well tested behind fakes, and never wired.** Five separate times
in Phase 3, every one of which passed the whole unit suite and all eleven vector classes:

1. The field merge was written and **unreachable** — a concurrent title/dueDate edit lost one.
2. §6.3.1's document gate was **never implemented** — a stale remote record overwrote a newer local
   one, for eleven types.
3. §6.9's settings merge stored **wholesale inbound** — a remote push reverted a local preference.
4. §7.15's purge and projection delete had **no call site** — a deleted note stayed visible and the
   next first sync re-pulled its body.
5. `PushSealer` had **no production implementation** — every impl was a test fake, and `memry-cli`
   had never pushed anything to a server.

**Treat "it is implemented" as unproven until you find the production call site.** A `grep` for the
caller is a five-second check that would have caught all five. Phase 4 is a shell wiring a core:
this is precisely the failure mode it is shaped to produce. Every seam you land, prove something
real calls it.

**Second lesson: five test assertions passed under the very bug they were written for.** They were
found only by deliberately breaking the code and watching which tests stayed green — including a
convergence test that passed byte-identically while the document silently lost a block. **Break
every new assertion, watch it fail, restore it, and report what you observed.** Make every subagent
do this and report it.

## Known bugs the shell will trip over — do not rediscover, and decide deliberately

These are real, recorded in HANDOFF.md, and none is a Phase 4 task. Each one will look like a
Phase 4 bug when it bites.

1. **A permanently-rejected record wedges the whole outbox.** A `400` for one item's type fails the
   **batch**, the row keeps `attempt_count 0` with no backoff, and it retries forever — a legitimate
   record queued beside it never leaves the device. **The most serious open item in the tree.**
   Reachable by shipping a client that writes an item type before the server accepts it.
2. **Pull-then-push is not a convenience.** A client that pushes a field-merged type **without
   pulling first** silently destroys a concurrent peer's field, and no later pass repairs it: the
   server stores the payload verbatim (§6.10) and §6.5.2 P3 forbids the merging client from
   re-pushing. `SyncEngine::run_pass` does pull-then-push; any shell-driven sync must too.
3. **A whole-fragment replace loses concurrent edits** (defect 88, chapter 12 §12.5.0.1). Desktop's
   external-file-edit path does one. Anything in the shell that re-seeds a document from an external
   source of truth is an authoritative overwrite, not an edit.
4. **A delete must tick its clock** or the server accepts it and does nothing (§6.9.1).
5. **§7.15's runtime obligation is reported, not performed**: `PullReport::purged_documents` and
   `BodyPullReport::advanced_documents` name ids a registry holder must act on. **The shell is that
   holder.** Nothing acts on them today; a resident document goes stale and a purged one stays
   resident. This is Phase 4's to wire.
6. **`Reachability::observe` has no caller.** The seam doc now says draining on the transition is the
   **shell's** obligation. T146 is where that gets wired, or it stays unwired and the queue waits
   for a timer.
7. **`snapshot_is_due` has no caller.** §7.13.3's cadence exists in the core and nothing polls it.
8. A no-op pull costs **32–36 s** on a 94-note vault. Use `memry notes fetch <id>` for a cheap
   single-document probe (0.4–1.8 s) when measuring anything.
