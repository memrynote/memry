# Implementation Plans

Generated by the `improve` skill on 2026-06-12 (full standard audit, plans 001–009)
and extended on 2026-06-13 (direction-only audit, plans 010–012), both at commit
`86ee0cd1`. Each plan is self-contained: an executor with zero prior context can run
it from the plan file plus the repo. Read the whole plan, honor its STOP conditions,
and update your row when done.

Audit scope: full-repo `standard` pass across all nine categories (correctness,
security, perf, tests, tech-debt, deps, DX, docs, direction), hotspot-weighted
toward the sync engine, sync-server, and IPC boundary. **Not deeply audited:**
`apps/marketing-emails`, `apps/docs` content correctness, the renderer editor
internals (BlockNote/CriticMarkup) beyond known-debt leads, and exhaustive
dependency-CVE triage (the dependency-audit subagent's transitive-CVE claims were
**not** independently re-verified and are intentionally excluded from the plans
below — run `pnpm audit --prod` separately if you want that).

## Findings considered and rejected

Recorded so they aren't re-audited next run:

- **"Committed `.env` files (`apps/landing/.env`, `apps/desktop/.env`)"** — rejected as stated: those files are gitignored (`.gitignore:20` = `.env*`) and untracked. The real, retained issue is real values in the committed **`.env.example`** (plan 001).
- **"OTP request enables email enumeration"** — rejected: `handleOtpRequest` (`apps/sync-server/src/routes/auth.ts:90`) always returns a constant `{ success: true, expiresIn }` and emails any address; there is no user-existence oracle. By-design passwordless behavior.
- **"Y.Doc `update` listeners are an unbounded memory leak"** — rejected as stated: in both the close path (`crdt-provider.ts:226-227`) and compaction (`:736-741`) the doc is dereferenced from the `docs` map around `destroy()`, so the listener closure becomes GC-reclaimable. Not an unbounded leak; at most a style nit.
- **Transitive-dependency CVEs (fast-uri / ajv / smol-toml)** — not rejected, but **not independently verified** in this pass; deliberately excluded from the plan set rather than asserted on a subagent's say-so. Triage with `pnpm audit --prod` if desired.
- **Calendar 100-year virtualizer (`use-week-infinite-scroll.ts`)** — low impact (TanStack virtualizer only materializes visible columns); not worth a plan now.
- **`repair:links` pre-step before typecheck/test** — a real DX smell but the root cause (pnpm workspace symlink behavior) is unclear and the script is an effective mitigation; not worth a speculative plan. Documenting it (a comment + a CLAUDE.md troubleshooting line) is a cheap follow-up if it bites contributors.
- **TypeScript 6.0.3 upgrade** — optional; no concrete cost to staying on 5.9.3 right now. Defer.

From the 2026-06-13 direction audit:

- **"Paid sync unimplemented"** — subagent finding, factually wrong: Paddle webhooks (`apps/sync-server/src/routes/webhooks.ts`), entitlement gating (PR #523), billing UI and web account area (PR #527) are shipped.
- **"Task reminders missing"** — stale: shipped in PR #538 (2026-06-12). The residual app-core/CLI drift is already plan 005.
- **"Agent backend selector missing from desktop UI"** — rejected: provider/model/reasoning are per-conversation settings in the existing Agent Chat UI.
- **Vault backup/restore (encrypted whole-vault snapshot)** — real gap (no `vault backup` in CLI or app-core), deferred by maintainer choice on 2026-06-13; strong post-launch candidate.
- **Agent/CLI/MCP tool-surface parity sweep** — real: MCP has no reminder tools and no task/project search (`apps/desktop/src/main/agent/mcp/tools/schemas.ts:394` — only `vault_search_notes`); `journal.dayContext` returns hardcoded `events: []` (`packages/app-core/src/memry-app.ts:105`). Deferred by maintainer choice; good post-launch S–M batch.
- **Email-in / HTTP capture API** — real gap (`'api'` capture source exists unused; README promises "Email-yourself-a-note"); E2E-encryption tension needs a design decision; deferred post-launch.
- **Self-hosted sync server, locked spaces, shared vaults, plugin API, templates marketplace** — "Planned"-tier roadmap items, zero code, L–XL each; wrong side of the launch window.
- **CalDAV/Outlook calendar providers** — L per provider, high recurrence/timezone risk; post-launch.
- **Bulk note operations / cascade-delete options in MCP & CLI** — minor; post-launch.

## Direction findings (options for the maintainer, not problems)

Grounded options, not ranked problems. The 2026-06-13 direction audit promoted
three of these into design-spike plans (010 web clipper, 011 importers, 012 task
focus mode). Still open:

- **Public vault sharing** (encrypted, view-only). In the README roadmap with
  zero spec/code; needs a key-derivation/crypto spike first.
- **CLI discoverability**. `apps/cli` has a full ~47-subcommand surface but no
  `--help`/usage tree and thin user docs — cheap to productize the scripting story.

inbound half exists" was wrong. Outbound push exists and is gated by the
`pushEventsToGoogle` setting in `apps/desktop/src/main/calendar/google/sync-service.ts`
(PR #529/#539 added the _option_ to disable it for inbound-only sync).
