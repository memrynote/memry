## Fixed decisions (do not revisit)

- **D1 Entry point.** More › Calendar, with More selected in the tab bar (as drawn). No new tab. Deep links (`memry://calendar?date=&event=`) open Day on the date with the item sheet, like desktop's Agent Chat focus.
- **D2 Data path.** iOS subscribes to the four calendar record types and computes the projection locally in `memry-core`, the same way desktop `main/calendar/projection.ts` does: memrynote events, external events, tasks with due dates, reminders, inbox snoozes, note date properties and inline note dates. Parity is pinned by conformance vectors generated from desktop.
- **D3a Calendar settings are two-way (Kaan, answered).** Any calendar setting changed on desktop or iOS takes effect on both. Today only `calendar.weekStartDay` is in the settings sync schema (`packages/contracts/src/settings-sync.ts`); `showNotesOnCalendar` and the per-provider groups (`calendar.google`, `calendar.<providerId>`: push toggle, AI read consent, default target, promote "don't ask again") are device-local on desktop. This spec extends the `calendar` sync group to carry them, on both desktop and iOS (CL018). Stays device-local by nature, and says so in the UI: This Mac / This iPhone enablement and their per-calendar switches, provider secrets and tokens, sync cursors. Source selection ("Not syncing" ticks) travels on `calendar_source` records, not settings; verify in CL003.
- **D3 iOS is a full provider device (Kaan, answered).** Accounts can be connected, reconnected and disconnected on iOS: Google (OAuth), CalDAV (all presets), Subscribed (ICS / webcal). iOS runs the provider runtime itself, the way a second desktop does today; it does not depend on a desktop being online. This follows the existing multi-device model: each device with a connected account polls it, and desktop's write routing (`provider/write-routing.ts`: live binding > event target > default target, oldest binding wins) guarantees exactly one provider pushes each item. iOS implements the same rules, so:
  - **Pull:** Google incremental sync (sync tokens, cursor reset on 410), CalDAV (`ctag` / `sync-token` / etag), ICS fetch with the same limits and error kinds (`settings.json` `subscriptions.errors`). On foreground, on pull-to-refresh / Sync now, and via `BGAppRefreshTask`; realtime nudges from the sync server where desktop uses Google push channels (`sync-server/src/routes/calendar-channels`, `webhooks`), if available to iOS (CL003).
  - **Push:** memrynote events, tasks, reminders and snoozes to the routed provider, honoring the push toggle, bindings and `writer-compat` (older-device notice).
  - **Auth:** Google via `ASWebAuthenticationSession` + PKCE with an **iOS OAuth client** (reversed client-id URL scheme); CalDAV basic auth / app password. Tokens and passwords live in the iOS Keychain only, never in records or settings. Device linking's provider-auth transfer (`google/provider-auth-transfer.ts`) hands accounts to and from iOS, or each device signs in itself; CL003 decides by whether a refresh token is usable across the desktop and iOS client ids.
  - Where the logic lives (Rust core vs Swift: ICS / iCal parsing, recurrence expansion, write routing, field mapping from `google/mappers.ts` and `ical/**`) is decided in CL003 by one rule: anything that must behave identically across devices is in core and pinned by desktop vectors; transport (URLSession, Keychain, background tasks, auth UI) is Swift.
  - Disconnect on iOS removes that device's credentials and follows desktop's disconnect semantics for synced sources; it never deletes another device's credentials.
  - Record writes are the same whether or not a provider is connected on iOS: events CRUD, move / resize, project link, promote (`calendar_event` + `calendar_binding` exactly as desktop `promote-external-event.ts`), source selection, settings. A write routed to a provider this device has no credentials for is pushed by the device that has them.
- **D4 This iPhone** reads EventKit (`EKEventStore.requestFullAccessToEvents`) on-device only, read-only, never synced to other devices. It mirrors desktop's device-local `apple-eventkit` provider and its duplicate guard (a calendar already connected via Google / CalDAV starts off).
- **D5 Timeline ships on iPhone** (07–09), overriding the Tasks audit's "desktop only" note.
- **D6 Rust core changes are authorized** for: subscribing the four types, storage and projectors, field-level merge matching desktop `field-merge-calendar.ts` (field clocks from migration `0026`), a read API (range projection, sources, event, external event details, search) and a write API (create / update / delete event, move, link project, promote, source selection, provider settings), UniFFI surface and the Swift seam. Protocol doc chapter 13 gains the four payload schemas; chapter 05's subscribed list is updated.
- **D7 Backward compatibility is mandatory.** Subscribing is additive: older iOS builds keep omitting the types. iOS must round-trip every field it does not understand (unknown keys, `fieldClocks`, provider metadata) untouched. Desktop code changes are limited to D3a (settings sync extension) and to bugs a conformance vector exposes (logged, separate `fix(desktop)` commit). D3a compat plan: new keys are optional and additive; an older desktop that does not know them must neither drop nor overwrite them when it re-uploads settings (per-key field clocks; prove it with a test that replays an old-schema upload over new values); on first run a device seeds each new key from its local value only if the synced value is absent, so an existing install never loses its choice.
- **Anything else ambiguous:** pick desktop's behavior, log it in §6, continue. No questions to Kaan.

## Rules (non-negotiable)

- **Behavior parity.** Every row of the 00 audit and every arrow of 00b is reachable at the place named. Undrawn desktop behaviors still ship at the nearest native spot: overlap lanes, span clipping per week row, "N more" in month cells, ended-event fade, triggered reminder fade, custom event color replacing the type hue, "Not syncing" subscribe-on-tick, Google refresh, per-tab view state (per device on iOS), today-request scroll, week start setting, time-zone handling from `calendar-date.ts`, all-day UTC-midnight exclusive end, promote "ask every time while AI access is off", save-error messages, project-link failure keeping the created event.
- **Scope.** iOS provider runtime (`Features/Calendar/Providers/**` + core modules per D3), iOS app config for the Google iOS OAuth client and URL scheme, `packages/contracts/src/settings-sync.ts` + desktop settings sync / calendar settings read-write paths (D3a only), `crates/memry-core/**` (calendar only), UniFFI + generated Swift, `apps/ios/Memry/Features/Calendar/**` (new), `apps/ios/Memry/Design/**` (shared primitives only), `Features/Notes/VaultTabsView.swift` / More list entry, deep-link routing, `packages/contracts` vectors, `docs/protocol/05` and `13`, tests, this spec, `apps/ios/SpikeEvidence/calendar/`. Touching Tasks, Inbox or Notes is limited to the navigation hooks lane E needs (open task detail, When sheet, inbox focus, note at anchor); reuse their public views, don't fork them.
- **Native iOS 26 first**, per artboard 00's SwiftUI column: `toolbarTitleMenu` + `Picker`, `ToolbarItemGroup` + `ToolbarSpacer` glass, `.buttonStyle(.glass / .glassProminent)`, `.sheet` + `.presentationDetents([.fraction(0.35), .medium, .large])`, `.contextMenu(menuItems:preview:)`, `Menu` + `ControlGroup` icon rows, `.alert` / `.confirmationDialog`, `DatePicker(.graphical)`, `.searchable` or a glass search field, `LongPressGesture.sequenced(before: DragGesture)` with `.sensoryFeedback(.selection)` per snap, `safeAreaInset(edge: .bottom)` composer, `ScrollView(.horizontal)` + `.scrollTargetBehavior(.paging)`, `ASWebAuthenticationSession`, `BGAppRefreshTask`, Keychain, `EventKit`. No hand-drawn glass, switches, segmented controls or pickers when the system has one.
- **Same design language as iOS Tasks.** Reuse spec 005 primitives (glass capsule, pills, composer chip, undo toast, sheet confirm, `taskGlass` fallback, `TitleMenuHeader`). Calendar type hues become tokens (`Tokens.Calendar`: indigo event, violet imported, green task, cyan reminder, amber snooze, pink note, dashed pink date reminder, plus the 11 Google event colors from `calendar-colors.ts`), light and dark. Values from Paper via `get_jsx` / `get_computed_styles`, mapped to `Tokens`; no new hex in views, no `Font.system(size:)`; 17/15/13 px = body / subheadline / footnote.
- **Interaction rules from 00.** Tap opens, long press acts, hold + drag moves; only memrynote events and timed tasks move. Every item opens a sheet, never a popover. Read-only stays visibly read-only. One primary action per screen. Glass only on chrome; the tint fills with an ink glyph, tinted text uses `Tokens.Text.tint`.
- **Accessibility.** VoiceOver: every chip reads "type, title, time, calendar"; custom actions (open, move 15 min earlier / later, complete for tasks, delete); the grid is navigable without drag (rotor over items, "New event at …" action on hour cells). Dynamic Type to AX5 (Day and agenda lists reflow; Week and Month fall back to a list at AX3+). 44pt targets. Reduce Motion (`calmAnimation`), Reduce Transparency solid fallback. Leading / trailing only; RTL mirrors the week strip and time gutter. WCAG AA light and dark.
- **Localization.** Strings go through a `CalendarCopy*` pattern mirroring `calendar.json` and `settings.json` wording. Dates and times use `Date.FormatStyle` with the user's locale and the 12 / 24 h setting.
- **iOS rules** from `apps/ios/AGENTS.md`: no force unwrap / `try!`, `ErrorMapping`, `Log.swift`, feature Swift files ≤ 400 lines (`node scripts/check-line-ceilings.mjs`).
- **Performance.** Range queries only for the visible window ± one period; week / day paging does not refetch already-loaded ranges; the grid stays at 60 fps with 200 items in a week (measure with Instruments once, record in §5).
