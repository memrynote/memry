## THE DEEPER LESSON, from the bug a person found and no test could

**Spec-defect 136**: the phone could open a vault and read it, and **nothing could fill it**. Every
test built the store it then read. The screen *before* it worked, because the vault list is a network
read and the note list is local — so an account with 94 notes rendered "no notes" and looked like an
empty account.

**The rule**: when a surface is exported, ask what *feeds* it, and make at least one test start from
a state only the production path can reach. For Phase 5 this is sharp and concrete — **a test that
seeds a Y.Doc and then reads it proves nothing about whether the editor can ever put anything in
one.** The editor's equivalent of 136 is a bridge that round-trips beautifully in tests and never
receives a real keystroke.

## THE OTHER LESSON — assertions pass under the very bug they were written for

Phase 3 found five. Phase 4 found more, and these three are the shapes most likely to bite here:

- A `received.count == 256` stayed green under `.unbounded` — only the identity of both ends
  separates newest-256 from unbounded. **You are building a batching bridge; this is your shape.**
- An `AsyncStream` test **hung instead of failing** — 21 minutes of silence that looked exactly like
  a deadlock in the seam under test (defect 99). **Bound every wait. A test must fail, not hang.**
- A test's premise was "this is not configured yet", and it **inverted the day the feature started
  working** (defect 133). Two instances landed from one `Info.plist` edit; the first was caught and
  split out, the second was missed one file over and blocked the whole plan for hours.

**Break every new assertion, watch it fail, restore it, and report what you observed.** Aim for one
distinct failing test per break: if two breaks produce the same failure, the tests cannot tell those
bugs apart. When a break will not compile, the test was not carrying the weight you thought.

## Hard constraints — restate these in every subagent brief

- **PRODUCTION.** Real users run this on real data. Backward compatibility is mandatory. No DB
  resets; schema changes are additive, hand-written migrations.
- **Staging only. Never point anything at prod.** Staging `https://sync-staging.memrynote.com`,
  prod `https://sync.memrynote.com`. Subagents make **no network call** and do not read
  `~/.memry/staging/`. **Anything that touches Kaan's real account is the orchestrator's to run.**
  The account holds 94 real notes in one vault and three empty ones; Phase 3 put two test lines into
  Kaan's actual notes and had to clean them by hand.
- **The core owns the document; the guest persists nothing.** That is this phase's whole thesis.
  `websiteDataStore` is `.nonPersistent()`, and a guest that writes to `localStorage` or IndexedDB
  is a second source of truth.
- **The core never parses or serialises markdown** (chapter 12 §12.1). `extract_text` is its only
  text operation. T179's template seeding goes through `seed-from-markdown` on the **guest**, never
  a Rust markdown parser.
- **A whole-fragment replace loses concurrent edits** (defect 88, chapter 12 §12.5.0.1). Anything
  that re-seeds a document from an external source of truth is an authoritative overwrite, not an
  edit — and US4's Independent Test is explicitly about a concurrent desktop edit merging without
  loss.
- **Durability order is the task, not a detail** (T167, FR-030): append to `yjs_updates` and enqueue
  in `outbox` in **one transaction**, and advance the in-memory document only after it commits. The
  test asserts the order **against a call log**, not eventual appearance.
- **Constitution II: no raw error object is ever shown to a user.** `ErrorMapping.swift` is the whole
  of that rule. **Check that it covers every new core error enum** — this failed twice in Phase 4
  (`LinkingError`, then `SyncError`), both times falling through to the unrecognised arm, because
  those switches carry no `default:` by design. Test through the `any Error` funnel a catch block
  actually uses. `Log.swift` is the only logging path — `StaticString` plus a closed `LogDetail`, so
  a runtime string *cannot* be logged. **Do not widen it**, and never log note text.
- **An async core call cannot be cancelled from Swift** (defect 108) — `rust_future_cancel` appears
  **zero** times in the bindings. Never offer a Cancel over one.
- **Blocking versus async is contract, not an implementation detail** (defect 90). Blocking goes on
  `CoreExecutor`; async is awaited directly.
- **RTL and accessibility are not polish.** Logical properties, dynamic type, reduce-transparency and
  reduce-motion branched **at the modifier level**. **Localization is OUT of scope** (defect 98).
- **Line ceilings**: 600 per `.rs`; Swift `file_length` 600, `function_body_length` 100,
  `line_length` 160; `Features` files and **test files** are held to **400**.
- **Do not re-litigate** #2179–#2187.

## Known bugs and platform facts — do not rediscover

1. **A permanently-rejected record wedges the whole outbox.** A `400` for one item fails the
   **batch**, the row keeps `attempt_count 0` with no backoff, and it retries forever. **The most
   serious open item in the tree**, and it is why no copy may describe a permanent refusal as
   transient.
2. **Pull-then-push is not a convenience.** A client that pushes a field-merged type **without
   pulling first** silently destroys a concurrent peer's field, and no later pass repairs it.
3. **A delete must tick its clock** or the server accepts it and does nothing (§6.9.1).
4. **`packages/contracts`' `ScanLinkingRequestSchema` is wrong** — six fields where the route
   requires eight, `min(1)` where it requires a UUID. Any client written correctly against the
   shared contract cannot link. `apps/sync-server` is out of scope; it needs tracking server-side.
5. A no-op pull costs **32–36 s** on the 94-note vault. Use `memry notes fetch <id>` (0.4–1.8 s)
   when measuring.

## iOS facts that cost a session each

- **`swiftlint --strict --path <file>` does not exist.** Use `cd apps/ios && swiftlint lint --strict`,
  **run from `apps/ios`** — one directory up it silently lints the wrong set with no config. Run the
  **bare project-wide** form every wave; the per-file form is not the gate CI runs, and that gap kept
  `main` red for two entire phases.
- **A whole-plan run that writes NO xcresult is ONE TEST BLOCKED FOREVER, not a toolchain bug.** A
  unit test pressed a real Google button and `ASWebAuthenticationSession` waited for a human; nothing
  timed out, nothing logged. Find it in one run: `-parallel-testing-enabled NO`, then diff `started`
  against `finished` in the raw log — the stall is the last `started` line. **A unit test must never
  drive a seam that waits on a person.**
- **`test-without-building` silently runs a STALE binary when DerivedData paths differ.** Pair
  `build-for-testing test-without-building`, or pass the same `-derivedDataPath` the build used. This
  produced a completely convincing wrong answer.
- **`-only-testing:` with a name that matches nothing runs nothing and prints `TEST SUCCEEDED`**
  (defect 106). Suite names are **struct names, not file names**. **Precompute the expected total
  before reading the result** — the failure mode is a plausible smaller number, not an error.
- **`xcodebuild` lies about the count.** Real numbers **only** from
  `xcrun xcresulttool get test-results summary --path <bundle>.xcresult`.
- **Real-keychain tests must nest under `RealKeychainSuite`**; a SwiftLint custom rule enforces it.
  Swift Testing runs sibling suites in parallel and `.serialized` does nothing between siblings.
- **NEVER revert a break with `git checkout --`.** On an untracked file it silently does nothing; on
  a tracked file it destroys every uncommitted edit. Use an inverse patch or a byte-for-byte
  copy-back, **verified by hash**. And verify the revert after an *interrupted* sweep too — an agent
  re-recorded its md5 baseline from an already-broken file.
- **An exported type's Rust module path is part of its ABI** (defect 122). After any surface change,
  regenerate and confirm the generated Swift diff has **zero deleted lines** — unless you widened a
  constructor, in which case the only deletions are that declaration, and say so rather than claiming
  zero.
- `Thread.isMainThread` is unavailable from an async context under Swift 6; assert the **queue
  label** (defect 91).
- **No `project.pbxproj` edit is needed for a new file** — `PBXFileSystemSynchronizedRootGroup`.
- **The generated bindings are their own target at Swift 5**; `MemryCore` stays at Swift 6. Do not
  undo this. `Package.swift` links `libz`. Do not undo that either.
- **Turn off the simulator's hardware keyboard (⇧⌘K) and dismiss the QuickPath overlay before any
  editor or toolbar test** (R16) — both make a correct toolbar look absent with no error. **This
  phase is the editor and the toolbar**, so this is no longer a footnote.
