## THE LESSON FROM THE READ PATH — apply it to the write path

The read path looked finished. 314 unit tests were green, all eleven vector classes passed, and the
first real staging round trip still found **five wire mismatches**, four of them chapter omissions:

1. `POST /sync/pull` takes `itemIds`, not `ids`. Request body was never written down.
2. **The read envelope is not the write envelope** — pull nests the four ciphertext fields under
   `blob`, push sends them flat. 500 of 500 items came back malformed.
3. `GET /sync/vaults` sends `vaultUuid`, not `id` or `vaultId`.
4. That vault reader **silently dropped** rows it could not parse, so a field-name mismatch read as
   "this account has no vaults" against an account holding four.
5. `tag_definition.icon: null` was recorded corrupt, 146 times. No vector carries a null `icon`.

**So: assume the write path hides the same class of surprise, and that a write bug is worse,
because it writes to Kaan's real data.** Two rules follow.

- **Never let an unparseable response read as an empty one.** FR-032 states this for a zero-row
  first page; it applies to every reader. A parse failure is `MalformedResponse`, never a skip.
- **`Field::opt` versus `Field::opt_null` is invisible until a producer writes an explicit null.**
  When a projector touches a field the vectors do not exercise with a null, prefer `opt_null` and
  say why — §13.3's forward tolerance and data-model §A.4 both require substitute-never-refuse.

## Implementation follow-ups already recorded — fix or carry, do not rediscover

1. **`ApiError` has no storage variant.** `PushWave::pending/drain` return `ApiError`, so a local
   SQLite failure crosses as `ApiError::Transport { Failed { "local storage: …" } }`. Behaviour is
   right, the typing lies. Add `ApiError::Storage`, and consider `ApiError::PaymentRequired`.
2. **`apply_local_edit` and `apply_remote` cannot compose into one transaction** — both call
   `conn.unchecked_transaction()` and SQLite refuses a nested `BEGIN`. A caller wanting the §13.2
   rule-3 merge *and* its outbox row committed together needs `apply_local_edit_in(&Transaction, …)`.
   `outbox::enqueue` refuses autocommit, so the unsafe path is a runtime error rather than silent
   divergence — but the composition is missing and **W8's domain modules will hit it**.
3. §7.13.3's snapshot **cadence** is unimplemented (the gate, watermark and prune are done). Nothing
   is incorrect — §7.13.1 says there is no MUST-snapshot — but a heavily edited document's server
   log grows unboundedly.
4. The socket has no self-driving `run()` loop; the whole reconnect policy is implemented and tested.
5. A pulled update does not advance an already-resident `Document` in memory; it lands on the next
   `load_plan` replay.
